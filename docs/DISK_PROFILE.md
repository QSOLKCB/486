# `diagnostic-disk-v1` lab device

This extension is a project-specific diagnostic interface, not an ATA,
floppy, BIOS or DOS disk. It uses the text profile's instruction subset without changing
`diagnostic-real-v1`; this disk guest maps only ports E9 and D0–D3 and starts
with the base profile's zeroed segment registers. Keyboard ports are not mapped. Guest instruction access uses byte `IN AL,DX` (`EC`) and
`OUT DX,AL` (`EE`). These preserve flags. No DMA, interrupts or wall-clock timing
are modelled. The CPU performs each port operation synchronously.

The immutable base consists of 16-byte logical sectors, at least one and at most
256 sectors. This intentionally tiny sector size is a lab protocol, not PC media.
The four individually routed byte ports have the following deterministic behavior:

| Port | Read | Write |
|---|---|---|
| `D0` | selected sector | select sector 0–255 |
| `D1` | buffer offset | select byte offset |
| `D2` | selected buffer byte | replace selected buffer byte |
| `D3` | status | command: 1 read sector into buffer; 2 stage buffer as overlay |

Offsets outside 0–15 produce status 1 and reads return zero; no buffer mutation
occurs. Command 1 reads staged data if present, otherwise the last committed
overlay or immutable base. Command 2 copies the complete buffer into a volatile
staged overlay. An out-of-range sector produces status 1 without mutation; unknown
commands produce status 2. A reset clears the buffer, selectors, status and volatile
staging while preserving the selected base and last committed overlay. Status 3
indicates guest writes are unavailable during a host save. No disk data is sent to
a network service. The UI controls the explicit save; a staged guest write is not
yet durable. The diagnostic guest reads a known byte, changes it by issuing port
writes, rereads it, outputs the observations, then halts.

Base identity is SHA-256 of exact bytes plus byte length; filenames are labels only.
The persistent store additionally validates sector size and schema/profile. A save
atomically writes all changed sectors and a new revision in one IndexedDB
read-write transaction after checking the expected revision. Competing stale
writers fail instead of overwriting. The UI may report committed only from the
transaction completion event; request success is insufficient. Failure, abort or
quota exhaustion leaves the previous revision readable. Reset invalidates pending
host work; already completed storage commits survive but stale completions cannot
mutate the active machine. Export assembles the immutable base and a single
committed overlay snapshot, excluding volatile uncommitted changes. Browser storage
may be evicted, so export is the portable copy.

## Original test fixtures

Both fixtures are authored for this repository under Apache-2.0; neither contains
third-party disk or program material. `fixtures/disks/lab-disk.mjs` generates exactly
64 bytes, byte `i` = `(7*i + 0x41) & 255` for `i=0..63`. Its SHA-256 is
`bd7d3e1e3ae1f865f14bdedd36a4c116d9db776aa6768a4d06ab269f2c0be5cb`.
`fixtures/diagnostics/disk.mjs` generates the 50-byte program from literal documented
x86 opcodes; its SHA-256 is
`5807c9425aa3733d1c4fb8cde5288640dabc7c257a269924875c9d240187e7a9`.
Reproduce with Node.js 24.22.1 and `node:crypto` SHA-256, or any implementation of
SHA-256 over the generated bytes. The expected output is `AZ` from port E9; this
observation is a test oracle, never an execution input. The guest stages `Z` at byte
zero of sector zero. Explicit host save commits the overlay.
